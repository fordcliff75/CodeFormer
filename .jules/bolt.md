
## 2024-05-12 - [Python List Processing Overhead vs Math]
**Learning:** Even simple built-in Python list functions like `max()` over mapped attributes and `list.index()` carry measurable overhead inside tight loops that are repeatedly executed (like calculating bounding box sizes or distances to center points). In this specific codebase, calculating pure-Python squared Euclidean distance via a list comprehension or replacing a list map-then-reduce pattern with a single-pass tracking loop yields significant micro-optimizations that completely bypass the overhead of intermediate NumPy array instantiations and `.linalg.norm` calculations.
**Action:** Always scrutinize nested list iterations that perform math in this codebase. Prefer single-pass mathematical loops or pure-Python list comprehensions without NumPy wrapper objects where applicable, ensuring inline comments are always added to explicitly document these exact speed-vs-allocation tradeoffs as required by the agent persona.
