## 2024-05-24 - Tensor to Image Conversion Performance Optimization
**Learning:** `tensor2img_fast` was fundamentally broken for single-channel 3D tensors (e.g. grayscale) as `.squeeze(0)` indiscriminately stripped the single channel dimension when `c=1`. Additionally, it was truncating data by casting float scales direct to `uint8` without rounding, breaking fidelity with the default `tensor2img`. Pushing operations to the GPU before CPU transfer significantly increases performance for these conversions by reducing data size 4x over the PCIe bus.
**Action:** When creating high-performance fast-paths (like moving tensor ops to GPU before CPU transfer), ensure exact parity with the slow-path by checking bounds (e.g., `tensor.dim() == 4`) and matching rounding behaviors (e.g. adding `.round()`) to prevent data truncation.
