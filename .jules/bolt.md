## 2024-05-24 - [GPU Post-Processing & Caching Allocator Bottleneck]
**Learning:** Performing tensor-to-image post-processing (scaling, rounding, casting to uint8) on the GPU via `tensor2img_fast` before transferring to CPU reduces data sent across the PCIe bus by 4x, significantly improving performance compared to doing these operations on the CPU (`tensor2img`). Also, using `torch.cuda.empty_cache()` inside an inference loop forces global GPU synchronization and releases memory to the OS, which defeats the purpose of the PyTorch caching allocator and severely degrades loop performance.
**Action:** When working on PyTorch image processing models, always move lightweight scaling/casting operations to the GPU before `.cpu().numpy()` transfers. Ensure `torch.cuda.empty_cache()` is never used within inference or training loops unless strictly necessary for handling dynamic memory spikes.
