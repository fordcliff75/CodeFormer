## 2024-06-21 - [Implicit Code Review and Instructions Parsing]
**Learning:** We missed adding an explanatory inline comment for the optimization during the first run. The prompt's strict instruction to `Add comments explaining the optimization` applies directly to the code being changed, not just the PR description. Furthermore, unnecessary file modifications like `basicsr/VERSION` (a side-effect of `pip install -e .` writing a dummy version due to lack of standard setup or git history) should be completely reverted to avoid polluting the PR, which was flagged during code review.
**Action:** Always read the user's explicit constraints (`✅ Always do`) verbatim and explicitly implement them in code using inline `# Optimize: ` comments. Second, aggressively use `git restore` on ANY file tracked or untracked that was modified purely as an environment side-effect (e.g. `VERSION`, `test_fast.py`) before submitting the PR to ensure exact scope matching.
